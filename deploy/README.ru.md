# Развёртывание Roboport

[На главную](../README.ru.md) · [English version](README.md)

Для общего сервера используйте отдельный Linux-хост. Windows подходит для личного или локального сервера с Docker Desktop.

## Перед началом

- Скачайте **Source code** со страницы репозитория и распакуйте его либо скопируйте адрес клонирования из **Code**.
- Сохраняйте каталог проекта: в нём SQLite-база, учётные данные и миры Factorio.
- Не открывайте панель в Интернет без HTTPS. В Linux само приложение по умолчанию слушает только loopback.

## Установка

### Linux: Debian или Ubuntu

На выделенном хосте в корне распакованных исходников:

```bash
cd /path/to/extracted/roboport
INSTALL_SYSTEMD=yes INSTALL_NGINX=yes INSTALL_TLS=selfsigned bash deploy/install.sh
```

Установщик поставит Python, Docker и nginx, создаст `.venv` и `.env`, включит Docker и `roboport.service`, выпустит самоподписанный сертификат. При наличии mDNS он также объявит `<hostname>.local`. Если установщик добавил вашу учётную запись в группу `docker`, перелогиньтесь.

Откройте `https://<hostname>.local/` или IP-адрес хоста и подтвердите предупреждение о самоподписанном сертификате. До подтверждения сверяйте его: **Настройки панели → Сеть и адрес → HTTPS-сертификат → Сведения о сертификате** показывает отпечаток SHA-256. В этом режиме Roboport слушает `127.0.0.1:8001`; nginx выдаёт HTTPS на 443 и перенаправляет HTTP с 80. На хосте отпечаток выводится так:

```bash
sudo openssl x509 -in /etc/nginx/roboport-tls/cert.pem -noout -fingerprint -sha256
```

Для публичного домена используйте `INSTALL_TLS=certbot` и задайте `SERVER_NAME=panel.example.com`. После настройки DNS на этот хост и открытия порта 80 установите Certbot с плагином nginx и запросите сертификат:

```bash
sudo apt update
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d panel.example.com
```

`INSTALL_TLS=none` — HTTP без шифрования, для Интернета не подходит.

```bash
sudo systemctl status roboport
sudo journalctl -u roboport -n 100 --no-pager
sudo systemctl restart roboport
SMOKE_BASE=http://127.0.0.1:8001 bash deploy/smoke.sh
```

### Windows 11: Docker Desktop с WSL 2

Для личного использования Docker Desktop бесплатен. Организации могут проверить, нужна ли им платная подписка, в [условиях Docker Desktop](https://docs.docker.com/subscription-billing/desktop-license/).

Установите Docker Desktop, включите WSL 2 backend и запустите Docker Desktop. Затем откройте PowerShell в корне распакованных исходников:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\install.ps1
```

Скрипт может установить Python 3.13 и Docker Desktop через `winget`, создаёт `.venv`, `.env` и `start.bat`. Если Docker Desktop был установлен этим запуском, запустите его (и перезагрузите Windows, если он попросит), затем повторно выполните установщик.

Запуск — двойным щелчком по `start.bat`. Панель доступна только на этом компьютере: `http://127.0.0.1:8000/`. Необязательная запись автозапуска называется `Roboport.bat` и запускает ту же панель после входа в Windows.

## Первый запуск

При первом открытии `/setup` введите код из терминала установщика и создайте администратора. Код действует 10 минут. При ручной установке или для получения нового кода выполните на хосте `.venv/bin/python -m app.cli setup-code` (в Windows `.\.venv\Scripts\python.exe -m app.cli setup-code`). В **Настройки панели → Общее** укажите имя и токен Factorio.com для скачивания модов или публичного списка, а также при необходимости часовой пояс.

Выберите **Серверы → Создать новый сервер**, укажите свободный UDP-порт и запустите сервер. Для подключения извне разрешите игровой UDP-порт в межсетевом экране. RCON работает локально.

Для импорта существующего сервера поместите его папку прямо в `servers/` и нажмите **Импортировать** на приборной панели. Для импорта и клонирования нужны обычные файлы и каталоги. Если в папке есть символьные ссылки или точки соединения Windows, сначала замените их копиями нужных файлов и папок.

Включите 2FA в **Настройки панели → Безопасность** и сохраните одноразовые резервные коды. Такой код один раз заменяет код аутентификатора.

## Эксплуатация

### Резервная копия

Сохраняйте `.env`, `app/panel.sqlite` и `servers/`. В последнем находятся конфигурация Factorio, моды, журналы и миры.

Для согласованной копии работающей Linux-панели откройте вкладку **Сейвы** каждого запущенного сервера Factorio, нажмите **💾 Сохранить сейчас** и дождитесь завершения. Затем остановите эти серверы в UI перед архивацией `servers/`. SQLite копируется через backup API без остановки панели:

```bash
umask 077
cd /path/to/roboport
backup_dir="$HOME/roboport-backups/$(date +%F-%H%M%S)"
mkdir -p "$backup_dir"
.venv/bin/python -c 'import sqlite3, sys; s=sqlite3.connect("file:app/panel.sqlite?mode=ro", uri=True); d=sqlite3.connect(sys.argv[1]); s.backup(d); d.close(); s.close()' "$backup_dir/panel.sqlite"
cp .env "$backup_dir/.env"
tar -C servers -czf "$backup_dir/servers.tar.gz" .
```

В Windows откройте вкладку **Сейвы** каждого сервера, нажмите **💾 Сохранить сейчас**, остановите каждый сервер Factorio, завершите `start.bat` через `Ctrl+C`, затем скопируйте `.env`, `app\panel.sqlite` и `servers` на отдельный диск. После этого снова запустите `start.bat`.

### Восстановление

Восстанавливайте только доверенную копию. Сначала остановите `roboport.service` в Linux (или `start.bat` в Windows) и серверы Factorio. Сохраните текущие данные как страховочную копию. Миры восстанавливайте только в чистый `servers/`, не смешивайте старое и восстановленное дерево. Замените `app/panel.sqlite` согласованной копией и удалите старые sidecar-файлы `app/panel.sqlite-wal` и `app/panel.sqlite-shm`: их нельзя смешивать с восстановленной базой. Затем запустите службу:

```bash
sudo systemctl stop roboport
# восстановите .env и app/panel.sqlite; servers/ восстановите в чистый каталог
sudo systemctl start roboport
```

После восстановления мира выберите архив во вкладке **Saves** и сделайте текущим, пока соответствующий сервер Factorio остановлен.

### Обновление и откат

В Linux откройте **Настройки панели → Обновления** и нажмите **Проверить обновления**. Перед установкой панель делает резервную копию в `.backups/`. Настройки, учётные записи и миры сохраняются. После перезапуска отдельный процесс проверяет, что панель отвечает на настроенном порту и сообщает ожидаемую версию. Если проверка не проходит, он восстанавливает предыдущую версию кода. На этой же странице можно установить доверенный архив релиза или откатить обновление из истории.

**Первое обновление с беты.** На вкладке «Обновления» раскройте **Источник обновлений**, укажите `Hydrogell/roboport` в поле **Репозиторий на GitHub** и сохраните изменения.

Если служба панели уже работала под обычной учётной записью Linux, выполните команды ниже один раз. Тогда обновление сможет завершиться и после выхода пользователя из системы. Для новой установки это делает установщик.

```bash
panel_user=$(systemctl show -p User --value roboport)
sudo loginctl enable-linger "$panel_user"
sudo systemctl start "user@$(id -u "$panel_user").service"
```

В Windows остановите `start.bat`, сделайте копию, распакуйте новые исходники поверх установки, сохранив `.env`, `app\panel.sqlite` и `servers`, снова выполните `deploy\install.ps1` и запустите `start.bat`. Не заменяйте эти пути пустыми копиями из архива.

## Восстановление доступа

Команды Linux запускайте из корня проекта. В Windows замените `.venv/bin/python` на `.\.venv\Scripts\python.exe`.

| Ситуация | Действие |
| --- | --- |
| Забыли пароль | На входе откройте **Забыли пароль?** и нажмите **Записать код в журнал**. В Linux прочитайте 10-минутный код через `sudo journalctl -u roboport --since '10 minutes ago'`, затем введите его и новый пароль на `/recovery`. Если аккаунт один, поле логина можно оставить пустым. |
| Альтернатива через консоль хоста | Выполните `.venv/bin/python -m app.cli emergency-access` (Windows: `.\.venv\Scripts\python.exe -m app.cli emergency-access`), чтобы вывести одноразовый код для `/recovery`. |
| Забыт логин | `.venv/bin/python -m app.cli list-users` |
| Сброс пароля из консоли | `.venv/bin/python -m app.cli reset-password USERNAME` безопасно запросит пароль и завершит сессии пользователя. |
| Потерян аутентификатор, но есть резервный код | Введите резервный код в поле 2FA после пароля. Он одноразовый. |
| Потеряны аутентификатор и резервные коды | `.venv/bin/python -m app.cli disable-2fa USERNAME` отключит 2FA и завершит сессии пользователя. Войдите по паролю, снова включите 2FA и сохраните новые коды. |
| IP заблокирован | `.venv/bin/python -m app.cli unban IP_ADDRESS` |

`.venv/bin/python -m app.cli` без аргументов открывает интерактивную консоль хоста. Считайте коды восстановления, `.env`, копии базы и RCON-пароли секретами.

## Диагностика и ссылки

| Симптом | Что проверить |
| --- | --- |
| Панель Linux не запускается | `sudo journalctl -u roboport -n 100 --no-pager`, затем `sudo systemctl status roboport`. |
| Не работают действия Docker | Убедитесь, что Docker запущен. В Linux перелогиньтесь после добавления в `docker`; в Windows дождитесь **Engine running** в Docker Desktop. |
| Браузер не открывает панель | В Linux проверьте nginx и HTTPS-адрес; в Windows используйте `http://127.0.0.1:8000/` на том же компьютере. |
| К серверу Factorio нельзя подключиться | Проверьте его UDP-порт и правило firewall/NAT; RCON оставьте закрытым. |

Интерактивная документация API находится на вашей панели по пути `/api/v1/docs`. Переводчикам интерфейса: [docs/localization.md](../docs/localization.md).
